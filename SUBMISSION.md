**Project Description:**
```text
FixLine is a hands-free AI agent for industrial field crews. It covers repair, safety, quality, SCADA, shaft alignment, voice and vision, and project management capabilities across frameworks such as PMP, PRINCE2, and similar methods.

THE PROBLEM
A conveyor bearing fails at 2 a.m. in a plant in Lagos or Port Harcourt. The technician on shift is alone. The senior engineer is asleep. The manual is a PDF on someone's laptop. He does his best. Nobody checks that each step was actually done. Sometimes he skips lockout/tagout to save time. Lockout/tagout means locking the machine so it cannot start while someone is working on it. The machine runs again. It fails again a week later. The line loses hours of output, or someone gets hurt. The same site is also trying to run a 30-month power project in a spreadsheet.

That night shift is the story in the demo. The same failure happens in every industry where people fix machines in the field: oil & gas, power & utilities, manufacturing, mining, water/wastewater, food & beverage, pharma/life sciences, chemicals, pulp & paper, ports/terminals, data-center facilities, and building/plant maintenance.

WHY THIS IS PUSH THE FRONTIER
The hard part is not another chatbot. It is giving a person a new way to control a physical job: see the part, speak one checked step, and refuse to continue until the camera and the lockout say the work was done. A valve or a setpoint still cannot move until a person approves it. The plant safety system stays in charge.

THE LOOP — perceive → reason → confirm → enforce
It runs on Ray-Ban Meta glasses, or on any phone or screen. The Mock Device Kit is the glasses view in the browser (/glasses), so a judge can run it with no headset in the room.

- Perceive. Meta SAM 3.1 finds the part in view and outlines it.
- Reason. Muse Spark 1.3 reads the manual, the machine history, and the live trends. It speaks the repair one step at a time. Muse Voice Transcribe takes the question, so hands stay on the tools. SeamlessM4T (open weights) translates, so a technician who speaks Pidgin, Igbo, or French can still follow an English manual.
- Confirm. SAM 3.1 looks again after each step. The step does not count until the camera check passes. If the model is unsure which part it sees, the technician must confirm the highlight.
- Enforce. Work cannot start until lockout is confirmed. Fire guidance names the fire class, the extinguisher, and where to aim. A quality check must pass before the machine is signed off. SCADA writes wait for an on-screen approval. This app never changes a real valve.
```

**Describe your use of Meta products to build the submitted project:**
```text
FixLine is built on five Meta pieces. Each one does a job the others cannot.

- SAM 3.1 (sam-3.1) — the eyes and the check. It outlines the part in view and keeps track of it. It looks again after every repair step. If the box is missing, or the model is not sure, the next step stays locked until the technician confirms the highlight. The screen labels a stand-in box when the key is missing.
- Muse Spark 1.3 (muse-spark-1.3) via Meta Model API — the planner. It plans repairs from a spoken fault or a manual. It drafts every safety document, including the fire plan. It writes project plans and the project papers. It updates a live Gantt chart from a follow-up sentence. It explains alignment moves, reads plant alarms, and writes the shift quality report. Calls use an OpenAI-compatible chat endpoint. NVIDIA is the backup, not the primary.
- Muse Voice Transcribe (muse-voice-transcribe). Hands-free fault questions, project edits (“slip commissioning by 14 days”), and page changes (“open projects”). Hands stay on the tools.
- SeamlessM4T (Meta open weights). It translates speech and text, so instructions reach the technician in his own language, including English to French in Voice & Vision. Open weights means the model files can be run outside Meta’s hosted API.
- Ray-Ban Meta glasses + Mock Device Kit. The glasses view (/glasses) is built for that screen. Saying “open safety” or “open projects” lands on that section. The Mock Device Kit lets judges run the full experience in a browser, with no glasses in the room.

Together this is one loop, perceive → reason → confirm → enforce, not a single chat box pasted onto a manual.
```

**Why are Meta's models important to your solution?**
```text
FixLine has to see what the technician sees, and it has to show the work was done, on a real machine. SAM 3.1 outlines the part precisely enough to use as a pass or fail check. Muse Spark 1.3 is fast enough to talk someone through a repair, one step at a time, and it follows strict safety instructions. Muse Voice and SeamlessM4T make the guide hands-free and usable in local languages. Ray-Ban Meta glasses put that guide where the work happens: oil and gas, power, manufacturing, mining, water, food, pharma, chemicals, pulp and paper, ports, data centers, and plant maintenance. Together, these models are a second pair of expert eyes on the job, and a gate that will not let the next step start early.
```

**Feedback from your experience using partner technologies:**
```text
Meta Model API is the primary path. The live demo calls it first. NVIDIA Nemotron is the automatic backup. Nemotron runs on NVIDIA NIM, NVIDIA’s hosted model service. It answers when Meta has no key, returns an error, or takes too long. If neither can answer, the app uses a labeled offline template or the repair catalog. The screen shows which system answered, so the technician still gets a reply.

Vercel hosts the app. Putting a new version online was simple. Both APIs are OpenAI-compatible. They take the same style of chat request, so the backup code stayed small.

For later production, a partner stack is available and planned. It is for a backup way to run the models, and for a higher TPM. TPM means how much text the model can handle each minute. Meta Model API stays first. None of these three is connected in this build:

- Baseten. $100 in credits, and a high TPM for Muse Spark Open. That is a fast path for Meta open weights, the model files you can host yourself.
- Modal. $100 in credits for Meta open-weight Endpoints, hosted copies of those models. If we connect Modal, we can also use serverless GPUs and sandboxes. A serverless GPU is a cloud chip that turns on only for a job. A sandbox is a closed space for running code.
- Fireworks. $100 in credits for Meta open weights. Same planned role: a production backup and a higher TPM, with Meta Model API still first.

What I still want from the tools already in use: published rate limits, and more SAM examples in the docs for field equipment (pumps, valves, conveyors, MCC panels, not only general objects).
```

**Biggest obstacle:**
```text
The hard part was turning “the AI suggests a step” into “the step was actually done.” I solved it with the SAM check. Each step needs a camera look before the next one unlocks. Lockout must be confirmed before any work starts. The second obstacle was hardware. I could not count on glasses for every judge. I built against the Mock Device Kit, so the whole demo runs in a browser.
```

**Meta's models vs other models you've used:**
```text
Muse Spark 1.3 followed the step-by-step and safety rules more consistently than my NVIDIA backup. It also wrote clearer spoken instructions. The backup was a little faster on very short prompts, so it stays as the backup. For seeing and confirming parts, SAM 3.1 was the main reason to build on Meta.
```

**Please specify:**
```text
On a live machine, a wrong instruction can hurt someone. I need the model to follow instructions. I need strong vision, so the app can confirm the work. I need a short enough wait for spoken guidance. I need fair pricing. I also need an OpenAI-compatible API, the same request style many chat apps use, so I can keep a backup.
```

**What makes it hardest to switch:**
```text
The safety instructions and the camera check are tuned to how these models behave. Switching means testing every risky safety case again. A similar way to outline the parts is hard to find.
```

**What would most likely stop you from using Meta's models in production:**
```text
I would need clear promises on uptime, price, and support, and real availability for customers in Africa and on other industrial sites that cannot send camera footage to the cloud. Those plants need a way to run the models on their own computers, and clear rules for how long that footage is kept.
```
